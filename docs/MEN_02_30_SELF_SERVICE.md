# Самостоятельное подключение мужчин №2–30

Ян Первый не изменяется. Импорт Excel повторять не нужно.

## Порядок действий в Telegram

1. Откройте **👑 ADMINISTRATION → Мужчины** и выберите нужное имя.
2. **Сохранить HTTP-прокси**: вставьте индивидуальную строку Dolphin в формате `логин:пароль@IP:порт`; ссылка `https://b.intimcity.rip/`. Пароль прокси сохраняется зашифрованно.
3. **Проверить IP через Chromium**. Через некоторое время нажмите **Обновить статус Chromium**. Нужен результат «✓ Внешний IP и сайт подтверждены». Отдельная проверка HTTP CONNECT не заменяет проверку реального IP.
4. **Сохранить доступ к кабинету**: один раз укажите персональные логин и пароль Intimcity. Сохранённые ранее реквизиты повторно вводить не нужно.
5. **Проверить вход через Chromium**. Затем **Обновить статус входа**. Нужен результат «✓ Вход в Intimcity подтверждён».
6. Вернитесь в мастер и нажмите **Обновить статус этапов**; затем обновите список мужчин. Итог: «✓ Подключён · Вход подтверждён», 4/4.

## Если возникла ошибка

- **running / already_running**: обновите статус. Если проверка ещё не получила реквизиты и зависла, спустя 90 секунд станет доступен безопасный повтор без пароля. Уже забравшую данные проверку можно повторить только после защитного интервала, до 15 минут.
- **ip_mismatch / proxy_error**: проверьте именно персональный прокси; другой прокси или прямое соединение запрещены.
- **login_rejected**: проверьте, что это правильный личный кабинет; пароль перезаписывайте лишь если он ошибочен.
- **login_form_unavailable**: форма входа на сайте изменилась; не перезаписывайте пароль без необходимости.
- **github_* / callback_http_***: сбой выполнения, не ошибка мужских учётных данных.
- После замены прокси повторите IP-проверку; если старая запись Intimcity была привязана к предыдущей версии прокси, сохраните её заново.

## Неизменные правила

Каждый мужчина работает со своим проверенным прокси, закреплённым IP и своим зашифрованным кабинетом. Chromium проверяет IP **перед** отправкой формы. Изменение прокси или реквизитов сбрасывает старую техническую готовность. Пароли не выводятся в интерфейс и логи. Технически подтверждённый вход не предоставляет разрешения на публикации. У Яна Первого ничего не меняется.

Это проверенный путь, но сторонний сайт, CAPTCHA, сбои сети или GitHub могут потребовать повторения шага или вмешательства разработчика; абсолютную гарантию безотказности дать нельзя.
