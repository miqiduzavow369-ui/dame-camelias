# Подключение мужчин и завершение оценок

Зафиксировано 22 октября 2026 после реальной публикации Михаила (`yan_second`, анкета 690230).
Ян Первый (`yan_first`) — действующий эталон. Его вход, прокси и последовательность публикации не изменяются новым подключением.

## Карточка ADMIN: только три этапа

1. **Личный прокси.** Ввести одну HTTP-строку `логин:пароль@IP:порт`. Проверка сравнивает фактический выходной IP и открывает сайт через этот же прокси. Сохранение данных само по себе проверкой не считается.
2. **Кабинет Intimcity.** Ввести адрес сайта, собственные логин и пароль. Проверка входит через закреплённый прокси и подтверждает именно этот кабинет. Повторный ввод сохранённого пароля для проверок не требуется.
3. **Подтверждение владельца.** После двух успешных проверок владелец явно подтверждает подключение. Клиентский кабинет получает те же зашифрованные данные и версии. Само подтверждение не публикует оценки и отзывы.

До последнего шага карточка не обозначается как готовая к работе. Замена прокси, реквизитов или адреса аннулирует прежнее подтверждение соответствующих версий. Скрытие мужчины в клиентском кабинете управляется отдельно от подключения.

Техническое имя/email в каталоге сохраняется. Оно не заменяет фактический логин Intimcity и не является доказательством успешного входа.

## Единые обязательные правила для всех 29 остальных мужчин

| Связь | Обязательное поведение |
| --- | --- |
| ADMIN → клиентский кабинет | Один контракт `readSecondaryConnection`; готовность не выводится из нарисованной зелёной отметки. |
| Мужчина → данные | Собственные шифрованные прокси и кабинет, AAD и версии привязаны к accountId. Подстановка другого мужчины и fallback к Янy Первому запрещены. |
| Вход → IP | IP проверяется в том же браузере до входа; несовпадение останавливает выполнение. |
| Вход → кабинет | Успешный свежий вход своими реквизитами либо совпадающая подтверждённая идентичность. Заполненное поле логина не считается доказательством. |
| Перед отправкой | Подписывающий ключ результата доступен и проверен до запуска браузера; однократная граница отправки сохраняется до нажатия кнопки сайта. |
| Отправка → результат | Успех требует совпавшей записи собственного кабинета и подлинного JPEG. Принятый запуск GitHub не означает публикацию. |
| Результат → баланс | Сохранённый оригинал и завершение существующего резерва ровно один раз. Аккаунт списания берётся из финансового журнала. |
| Результат → группа | Тот же оригинальный JPEG и имя мужчины. Доставка учитывается отдельно от публикации. Неопределённый исход отправки в Telegram не повторяется вслепую. |
| Результат → Mini App | `secondaryStatuses` передаётся HTTP-маршрутом; завершённый архив восстанавливает состояние без зависимости от индекса черновиков. Кнопка открывает подтверждение, а не повторное заполнение. |
| Результат → подтверждение | Собственный JPEG читается из закрытого архива. Его content ID не передаётся в Telegram getFile как file_id. |
| Результат → дневной счётчик | Подтверждённая публикация учитывается один раз с accountId; записи Яна Первого сохраняют прежние ключи. |

Неопределённый результат сайта не разрешает повторную отправку. Восстановление уже опубликованной оценки и доставка сохранённого результата выполняются отдельно и не создают новое списание.

Общие критерии оценок сохраняются. Публикации и архивы разделяются по клиентке, мужчине, анкете и виду операции. Работа над модерацией отзывов — отдельная задача; её нельзя подменять этапом регистрации мужчины.

## Код и обязательные проверки

- `src/secondary_man_connection.js` — единственный контракт готовности и передачи собственного подключения.
- `src/cabinet_runtime.js`, `src/admin_app_api.js` — авторизация владельца и единый `man_registration_status`, не возвращающий секреты.
- `admin/preview-v3.html` — три этапа регистрации, автоматическое чтение статуса выполняющейся проверки, изменение сохранённых данных отдельно.
- `tests/secondary_connection_roundtrip.test.mjs` — все 29 связей ADMIN → клиент → подготовка → собственные данные исполнителя.
- `tests/all_secondary_completion_contract.test.mjs` — каждый из 29 ID, реальные модули учёта и HTTP-приёмки: собственный grant → однократная граница → подписанный JPEG → одно списание → одна доставка → архив, дневной счётчик и статус.
- `tests/man_registration_ui.test.mjs` — каждый из 29 ID во всех этапах и отдельный прежний экран Яна Первого.
- `tests/test_personal_login_evidence.py` — неизменность исходного пути Яна Первого и правила подтверждения входа.

Проверки используют синтетические данные и блокируют внешнюю сеть. Они не подменяют индивидуальную проверку настоящего прокси и кабинета при подключении каждого мужчины.
