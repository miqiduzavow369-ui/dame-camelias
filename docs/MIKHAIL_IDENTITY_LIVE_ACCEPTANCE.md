# Михаил Корсаков: приёмка подтверждения личности Intimcity

**Аккаунт:** `yan_second` (строго не `yan_first`).
**Статус:** инструкция для живой проверки, не свидетельство её прохождения.
**Без публикаций:** ни оценок, ни отзывов, ни списаний кредитов.

## Препятствия перед живым запуском

1. PR #207 пока не объединён с `main`; работающий Worker не содержит нового `login_authenticated_identity_verified` и серверного подтверждения по аккаунту.
2. Workflow `man-site-login-preflight.yml` запускается на `main`; для получения доказательства личности **и** его приёмки Worker и runner должны использовать одну проверенную совместимую версию кода.
3. Для реального результата необходима доступность личного HTTP-прокси, индивидуальных зашифрованных реквизитов Михаила и нужных секретов GitHub/Cloudflare. Не вводить пароли в Actions inputs, логи или комментарии.
4. CSS-селекторы видимого идентификатора в `tools/intimcity_authenticated_identity.py` ещё не подтверждены на реальной сессии. Отсутствие однозначного элемента = `identity_unverified`, не успешная проверка.

## Приёмка (после выкладки согласованной безопасной версии)

1. Войти в ADMIN владельца и открыть Михаил Корсаков (`yan_second`).
2. Проверить, что HTTP-прокси и фактический выходной IP закреплены за Михаилом.
3. Запустить штатную Chromium-проверку входа и получить отдельный код результата. Используется приватный одноразовый claim; runner не получает данные Яна Первого.
4. Chromium должен открыть Intimcity, авторизоваться, проверить видимую идентичность на странице авторизованного кабинета, а не значение поля логина.
5. Если результат `login_authenticated_identity_verified`, Worker сохраняет привязку к точным версиям proxy+site. Если `login_authenticated_identity_unconfirmed` либо `login_identity_mismatch`, личность **не подтверждена**.
6. В ADMIN проверить два независимых признака: `technicalReady` и `siteIdentityVerified`. Публикации **по-прежнему закрыты**, пока не собран отдельно проверенный персональный исполнитель.
7. Повторная проверка при смене прокси/реквизитов или отзыве ADMIN-разрешения должна инвалидировать прежнее подтверждение. Ни одна другая учётная запись не изменяется.
8. Снять безопасный протокол: ID GitHub Actions run, результат без персональных данных, версии конфигурации, время проверки и итоговый код. Пароли и полный HTML не сохранять.

## Критерии успеха

- `yan_second`: верный внешний IP, успешный вход, однозначное совпадение личности из авторизованного кабинета и закрепление за актуальными версиями настроек.
- `yan_first`: без изменений.
- Все остальные 28 мужчин: без автоматической активации до **их собственных** проверок.
- Никаких реальных публикаций или списаний за тест входа.
