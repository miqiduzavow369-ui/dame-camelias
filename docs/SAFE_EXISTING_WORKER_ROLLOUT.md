1. Получить **согласие владельца** именно на обновление существующего Worker. Подготовка PR не является согласием.
2. Из Cloudflare сохранить в защищённый архив **реальные** KV и DO; GitHub backup хранит только код. Установить текущие фактические остатки, израсходованные кредиты, резервы, анкеты и незавершённые операции.
3. Проверить совместимость GitHub Actions, версии Worker, nonce и payload; дождаться завершения действующих runner'ов.
4. До выкладки выставить в существующем Worker `CABINET_CLIENTS_ENABLED=false` и `CABINET_PUBLICATIONS_ENABLED=false` как обычные переменные среды (не новые секреты). **Важно:** отсутствие переменной означает включённую функцию; нельзя предполагать безопасный default.
5. Проверить CI на итоговом SHA, миграцию данных, действующий PIN владельца и пробного клиента, безопасность маршрутизации; до контрольного прогона не включать публикации.
6. Зафиксировать прежнюю версию Worker и GitHub workflow, а также готовую процедуру остановки.

## Остановка и откат
- При любой неопределённости первым действием поставить оба флага `false`; не очищать KV/DO, не перезапускать операции.
- Прежде чем возвращать старый Worker, дождаться завершения callbacks, сверить очередь settlement, расходы, claims и новые клиентские записи. После новых операций *слепой* rollback к старому коду может испортить остатки.
- Если восстановление старого кода безопасно не доказано, сохранить новый совместимый обработчик входящих результатов при выключенных новых действиях.
